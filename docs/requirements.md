# Eunhye Hymn 요구사항 (MVP + 운영 확장)

## 1. 목적
- 교회 내부에서 찬양 콘텐츠(악보 PNG, 파트 MIDI)를 안전하게 관리/소비한다.
- 관리자는 운영 화면에서 콘텐츠/권한/이력을 통제한다.
- 성도는 인증 후 모바일에서 빠르게 탐색/연습한다.

## 2. 범위

### 2.1 포함 범위
- 인증/인가
  - Kakao 소셜 로그인, ID/PW 로그인/회원가입
  - JWT access/refresh
  - 초대코드 검증 + SMS 인증
  - 회원 탈퇴
- 찬양/에셋
  - 찬양 CRUD, 활성화 관리
  - PNG/MIDI 업로드(presign/confirm)
  - 모바일 찬양 목록/상세/재생
- 개인화
  - 프로필 조회/수정
  - 개인정보 변경 요청 및 관리자 승인/반려
  - 즐겨찾기/메모/히스토리
- 운영
  - 감사 로그 조회/분석
  - CSV export(동기/비동기) 및 운영 지표
- AI
  - 상황 기반 찬송 추천 (`gemini-2.5-flash-lite`)

### 2.2 제외 범위(후속)
- MIDI 자동 파트 추출/편집
- 비회원 공개 접근
- 대규모 멀티테넌트 운영

## 3. 사용자 페르소나
- **관리자**: 찬양/에셋 등록, 권한 관리, 운영 로그 분석, 프로필 변경 승인
- **성도**: 로그인/검증 후 찬양 검색, 악보 열람, 음원 연습, 개인화 기능 사용

## 4. 기능 요구사항

### 4.1 인증/인가
- 로그인과 검증(초대코드/SMS)은 분리된 단계로 처리한다.
- 인증 성공 시 access/refresh 토큰을 발급한다.
- 역할은 `admin`, `member`를 지원한다.

### 4.2 찬양/에셋
- 찬양 기본 메타데이터(번호, 제목, 태그)를 관리한다.
- 에셋 타입은 `PNG`, `MIDI`를 지원한다.
- S3 presigned URL 기반 업로드를 지원한다.

### 4.3 개인화
- 프로필(교회/이름/구역/성별)을 저장한다.
- 프로필 변경 요청은 승인 기반으로 반영한다.
- 즐겨찾기/메모/히스토리를 제공한다.

### 4.4 운영/분석
- 관리자 액션과 사용자 이벤트를 감사 로그로 조회 가능해야 한다.
- CSV 내보내기와 비동기 대용량 export를 지원한다.
- export 처리 상태/실패율/처리시간 지표를 제공한다.

### 4.5 AI 추천
- 상황 텍스트를 기반으로 추천 찬송을 반환한다.
- 추천 사유를 함께 제공한다.
- 후보군/토큰/타임아웃 상한으로 비용을 통제한다.

## 5. 비기능 요구사항
- Clean Architecture 경계 준수
- API 계약 우선 문서화
- 관리자 경로 RBAC 적용
- 로컬/스테이징 재현 가능한 실행/배포 절차 유지

## 6. 성공 기준
- 관리자가 찬양+에셋을 등록/수정/삭제할 수 있다.
- 성도가 인증 플로우 완료 후 3분 내 핵심 화면에 진입 가능하다.
- 일반적인 목록 조회/검색 응답이 실사용 가능한 지연으로 유지된다.

## 7. 전제 및 리스크
- AWS/S3/Kakao/SMS/AI 자격증명 관리가 선행되어야 한다.
- 운영 시크릿 노출 방지와 정기 로테이션이 필요하다.
- AI 응답 품질/비용은 운영 데이터 기반 튜닝이 필요하다.
