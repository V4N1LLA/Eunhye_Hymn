# 유스케이스: JWT 인증 개요

## 목표
- 액세스 토큰으로 요청을 인증하고, 리프레시 토큰으로 재발급한다.

## 핵심 개념
- **Access Token**
  - 짧은 만료 시간.
  - `Authorization: Bearer <token>` 헤더로 전송.
  - 만료 시 재발급 필요.
- **Refresh Token**
  - 긴 만료 시간.
  - 서버에 해시 형태로 저장.
  - 재발급 시 기존 토큰을 폐기하고 새 토큰을 발급(로테이션).

## 만료 전략
- Access Token은 짧게(예: 1시간).
- Refresh Token은 길게(예: 14일).

## 설계 의도
- 액세스 토큰 유출 시 피해 범위를 줄인다.
- 리프레시 토큰 로테이션으로 재사용 공격을 줄인다.
